# ระบบจัดการหัวหน้าทัวร์ (Tour Leader Management) — เวอร์ชันต้นแบบสำหรับ Demo

เว็บไซต์ต้นแบบสำหรับให้ผู้ใช้งานทดลอง workflow ตั้งแต่ **สร้างงานทัวร์ → จัดหัวหน้าทัวร์ → เบิกจ่าย → เคลียร์งาน → ปิดงาน**
เพื่อใช้เก็บ Requirement เพิ่มเติมก่อนพัฒนาระบบจริง

> ⚠️ **ข้อมูลทั้งหมดในระบบนี้เป็นข้อมูลจำลอง (Mock Data)**
> ไม่มีฐานข้อมูล ไม่มี Backend ไม่มีระบบ Login จริง ไม่เชื่อมต่อโปรแกรมบัญชี และไม่มีการจ่ายเงินจริง
> ชื่อบุคคล บริษัทคู่ค้า เที่ยวบิน และจำนวนเงินทั้งหมดเป็นข้อมูลสมมติ

## 1. วิธีเปิด Demo

ต้องมี **Node.js เวอร์ชัน 20.9 ขึ้นไป** (แนะนำ LTS)

```bash
cd tour-leader-system
npm install
npm run dev
```

เปิดเบราว์เซอร์ที่ <http://localhost:4300>

> พอร์ต 4300 ถูกกำหนดไว้ในสคริปต์ `dev` แล้ว (`next dev -p 4300`) เพื่อไม่ให้ชนกับโปรเจกต์อื่นที่ใช้พอร์ต 3000

### คำสั่งอื่น ๆ

| คำสั่ง | ใช้ทำอะไร |
| --- | --- |
| `npm run dev` | รันโหมดพัฒนาที่พอร์ต 4300 (Hot reload) |
| `npm run build` | Build สำหรับ production |
| `npm start` | รันเวอร์ชันที่ build แล้ว |
| `npm run lint` | ตรวจสอบคุณภาพโค้ดด้วย ESLint |
| `npx tsc --noEmit` | ตรวจสอบ TypeScript |

**เทคโนโลยี:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · ฟอนต์ Noto Sans Thai

## 2. สิ่งที่ทดลองได้ใน Demo

### สลับบทบาทผู้ใช้ (มุมขวาบนของ Header)

ระบบจำลองผู้ใช้ 4 บทบาท เพื่อให้เห็นว่าแต่ละกลุ่มเห็นเมนูและปุ่มต่างกันอย่างไร

| บทบาท | เมนูที่เห็น | สิ่งที่ทำได้ |
| --- | --- | --- |
| **ผู้ดูแลระบบ** | ครบทั้ง 9 เมนู | ทำได้ทุกอย่าง รวมถึงตั้งค่าระบบ |
| **ฝ่ายจัดหัวหน้าทัวร์** (ค่าเริ่มต้น) | ไม่เห็น "เคลียร์งาน" และ "ตั้งค่าระบบ" | สร้าง/แก้ไขงาน จัดหัวหน้าทัวร์ เปลี่ยนสถานะงาน แต่ **อนุมัติเงินไม่ได้** |
| **ฝ่ายบัญชี** | ไม่เห็น "หัวหน้าทัวร์" และ "ตั้งค่าระบบ" | อนุมัติใบเบิก บันทึกการจ่าย ตรวจและปิดการเคลียร์งาน |
| **หัวหน้าทัวร์** | ไม่เห็น "หัวหน้าทัวร์", "รายงาน", "ตั้งค่าระบบ" | เห็นเฉพาะงาน/ใบเบิก/การเคลียร์งานของตัวเอง สร้างใบเบิกได้ |

### Workflow หลักที่กดทดลองได้จริง

1. **ภาพรวม (Dashboard)** — ตัวเลขสรุป 8 รายการ, ตารางงานใกล้เดินทาง, รายการเร่งด่วน, ปฏิทินย่อ, กราฟสรุปสถานะ, เอกสารใกล้หมดอายุ
2. **หัวหน้าทัวร์** — โมดูลหลัก ดูรายละเอียดที่หัวข้อ [2.1](#21-โมดูลหัวหน้าทัวร์-รายละเอียด)
3. **งานทัวร์** — สร้าง/แก้ไขงาน, **เลือกหัวหน้าทัวร์พร้อมคะแนนความเหมาะสม (0–100)**, **เตือนเมื่อเลือกคนที่ตารางซ้อน**, เปลี่ยนสถานะตาม workflow, Timeline ประวัติสถานะ
4. **ปฏิทินงาน** — มุมมองเดือน/สัปดาห์/รายการ, กรอง 4 มิติ, สีแยกสถานะ, ทำเครื่องหมายงานซ้อนและงานที่ยังไม่มีหัวหน้าทัวร์, สร้างงานจากวันที่, **ลากงานไปวางวันอื่นเพื่อเลื่อนวันเดินทาง**
5. **เบิกจ่าย** — สร้างใบเบิกหลายรายการในใบเดียว, แปลงสกุลเงินเป็นบาทอัตโนมัติ, ส่งอนุมัติ → อนุมัติ/ส่งกลับแก้ไข/ปฏิเสธ → รอจ่าย → บันทึกการจ่าย (จำลอง), Timeline การอนุมัติ
6. **เคลียร์งาน** — ตรวจค่าใช้จ่ายทีละรายการ (อนุมัติเต็ม/บางส่วน/ไม่อนุมัติ + ระบุเหตุผล), **คำนวณยอดสุทธิทันที**, ส่งกลับแก้ไข, นัดหมาย, ยืนยันรับ/จ่ายเงิน, ปิดการเคลียร์งาน (ปิดงานทัวร์ให้อัตโนมัติ)
7. **นัดหมาย** — มุมมองรายการ/ปฏิทิน, สร้างนัด, **ตรวจเวลาซ้อนแบบจำลอง**, ยืนยัน/เลื่อน/ยกเลิก
8. **รายงาน** — 7 รายงานพร้อมกราฟและตาราง, ตัวกรองช่วงเวลา, ปุ่มส่งออก Excel/PDF (แสดงข้อความว่ายังเป็นต้นแบบ)
9. **ตั้งค่าระบบ** — จัดการข้อมูลตั้งต้น 11 กลุ่ม (รวม **ประเทศ** และ **เส้นทาง**) + ผู้ใช้และสิทธิ์ (**ใช้ "ปิดใช้งาน" แทนการลบเสมอ**)

### 2.1 โมดูลหัวหน้าทัวร์ (รายละเอียด)

#### หน้ารายการ — ตาราง 6 คอลัมน์

Component: [LeaderTable.tsx](src/components/leaders/LeaderTable.tsx)

| คอลัมน์ | รวมข้อมูลอะไรไว้ |
| --- | --- |
| 1. หัวหน้าทัวร์ | รูป · ชื่อ–สกุล · ชื่อเล่น · รหัส · เบอร์โทรหลัก |
| 2. ประเภทและที่พัก | ประเภทหัวหน้าทัวร์ (Badge) · จังหวัด · ประเทศประจำ |
| 3. ความพร้อมรับงาน | สถานะ (Badge ชื่อสั้น) · วันที่พร้อมเริ่มงาน · คำเตือนเอกสาร · หมายเหตุ (Popover) |
| 4. พื้นที่และความสามารถ | ประเทศ/เส้นทาง · ภาษา · ทักษะเด่น — **รวมไว้คอลัมน์เดียว** |
| 5. งานปัจจุบัน | รหัสงาน (กดได้) · ประเทศ · ช่วงวันเดินทาง · สถานะงาน |
| 6. จัดการ | ดู · แก้ไข · เมนู ⋯ (Sticky ขวาสุด พื้นหลังทึบ) |

**กติกาการแสดงผล**

- แสดงประเทศ/เส้นทางสูงสุด 2 รายการ · ภาษาสูงสุด 2 Badge · ทักษะเด่นสูงสุด 2 รายการ · ที่เหลือยุบเป็น **`+N`** และเปิดดูทั้งหมดได้ใน Popover ([InfoPopover.tsx](src/components/ui/InfoPopover.tsx) — เปิด/ปิดด้วยคีย์บอร์ดได้ ปิดด้วย Escape)
- ตารางใช้ `table-layout: fixed` ตามสัดส่วน 22/15/15/25/15/8% พร้อม `min-width` รายคอลัมน์ → **ไม่มีข้อความล้นข้ามคอลัมน์ และไม่ต้องเลื่อนแนวนอนบน Desktop**
- ความสูงแถวคุมไว้ **105–140px** · ทุกเซลล์ `align-top`
- **สถานะในตารางใช้ชื่อสั้น** (`LEADER_STATUS_SHORT` เช่น "พร้อมตามวันที่") ส่วนชื่อเต็มยังใช้ในหน้ารายละเอียด ฟอร์ม และตัวกรองเหมือนเดิม
- ไม่มีงานปัจจุบัน → แสดงข้อความ **"ไม่มีงานปัจจุบัน"** (ไม่ใช่ขีดลอย ๆ)

**Responsive**

| ขนาดจอ | รูปแบบ |
| --- | --- |
| ≥ 1280px | ตาราง 6 คอลัมน์ |
| 1024–1279px | ตาราง 5 คอลัมน์ — ยุบ "งานปัจจุบัน" เข้าไปในคอลัมน์ความพร้อม |
| < 1024px | **เปลี่ยนเป็น Card List** — ไม่บังคับให้ผู้ใช้มือถือเลื่อนตารางแนวนอน |

**ตัวกรอง** ถูกยุบไว้ในปุ่ม **`ตัวกรอง (N)`** (N = จำนวนตัวกรองที่ใช้อยู่) เพื่อคืนพื้นที่ให้ตาราง — ตัวกรอง การค้นหา และการเรียงลำดับ **ทำงานเหมือนเดิมทุกตัว** (ตรรกะยังอยู่ที่ [leaderSearch.ts](src/lib/logic/leaderSearch.ts))

#### ฟอร์มเพิ่ม/แก้ไข = Step Form 5 ขั้นตอน

(ใช้ Component ชุดเดียวกันทั้งหน้าเพิ่มและหน้าแก้ไข)

| ขั้นตอน | เนื้อหา |
| --- | --- |
| 1. ข้อมูลทั่วไป | **แบ่งเป็น 4 Card** — ดูหัวข้อ "ขั้นตอนที่ 1" ด้านล่าง |
| 2. การติดต่อ | Accordion: **ช่องทางติดต่อ** / **ผู้ติดต่อฉุกเฉิน** (ทั้งคู่รองรับหลายรายการ) |
| 3. ความสามารถและพื้นที่ | Accordion 4 กลุ่ม: ภาษา (n) / ประเทศประจำ (n) / เส้นทางที่เชี่ยวชาญ (n) / ความถนัด (n) |
| 4. ประวัติการทำงาน | **สถานประกอบการที่เคยทำงาน** — คนละส่วนกับประวัติงานทัวร์ |
| 5. เอกสารและการเงิน | Accordion: เอกสาร / บัญชีธนาคาร |
| → ตรวจสอบข้อมูล | สรุปทั้ง 5 ขั้นตอน + ปุ่ม "แก้ไข" กลับไปยังขั้นตอนนั้น |

**สถานะของแต่ละขั้นตอน:** ยังไม่กรอก · กำลังกรอก · ข้อมูลครบ · มีข้อผิดพลาด
**Desktop** = Stepper แนวนอน (ไม่มี Horizontal Scroll) · **มือถือ** = "ขั้นตอนที่ X จาก 5" + แถบความคืบหน้าแตะได้

**ปุ่ม:** ยกเลิก · ย้อนกลับ · บันทึกฉบับร่าง · ถัดไป · ตรวจสอบข้อมูล · บันทึกหัวหน้าทัวร์

**พฤติกรรมตอนบันทึก**

- กด **"ถัดไป"** → ตรวจเฉพาะขั้นตอนปัจจุบัน · กด **"บันทึก"** → ตรวจทุกขั้นตอน
- **แสดงสรุปข้อผิดพลาดที่ด้านบนฟอร์ม** (กดเพื่อกระโดดไปขั้นตอนนั้น) และ **เลื่อนไปยังช่องแรกที่ผิดอัตโนมัติ**
- แสดงสถานะ "กำลังบันทึก…" และ **กันการกดบันทึกซ้ำ**
- **เตือนก่อนออกเมื่อยังไม่บันทึก** · เปลี่ยนขั้นตอนแล้วข้อมูลไม่หาย
- สำเร็จ → Toast + **เปิดหน้ารายละเอียดของคนที่เพิ่งเพิ่มทันที**

### ขั้นตอนที่ 1 "ข้อมูลทั่วไป" — แบ่งเป็น 4 Card

Component: [GeneralInfoStep.tsx](src/components/leaders/GeneralInfoStep.tsx)

| Card | ข้อมูลที่กรอก |
| --- | --- |
| 1. ข้อมูลส่วนบุคคล | รูป Profile · รหัส · คำนำหน้า · ชื่อ–สกุล (ไทย/อังกฤษ) · ชื่อเล่น · วันเกิด · เพศ · สัญชาติ · **ศาสนา** · **สถานภาพสมรส** |
| 2. ที่อยู่ปัจจุบัน | บ้านเลขที่ · อาคาร · หมู่ · ซอย · ถนน · แขวง/ตำบล · เขต/อำเภอ · **จังหวัด (บังคับ)** · รหัสไปรษณีย์ · ประเทศ · หมายเหตุ |
| 3. ประเภทและความพร้อมรับงาน | ประเภทหัวหน้าทัวร์ · สถานะพร้อมรับงาน · **วันที่พร้อมเริ่มงาน** · **รูปแบบการรับงาน** |
| 4. ข้อมูลระบบและหมายเหตุ | วันที่เริ่มร่วมงาน · **แหล่งที่มาของข้อมูล** · สถานะข้อมูล · หมายเหตุทั่วไป · หมายเหตุภายใน · ข้อควรระวัง · ข้อมูลระบบ (อ่านอย่างเดียว) |

**กติกาสำคัญของขั้นตอนนี้**

- **อายุไม่เก็บลงฐานข้อมูล** — คำนวณจาก `birthDate` ทุกครั้งที่แสดงผล (`calculateAge()`) เพราะอายุเปลี่ยนตามเวลา
- **ศาสนา เพศ และสถานภาพสมรส ไม่ถูกใช้คำนวณคะแนนความเหมาะสมกับงาน** — ตรวจสอบได้ว่าไม่มีการอ้างถึงฟิลด์เหล่านี้เลยใน `src/lib/logic/` ทั้งโฟลเดอร์ (ทั้งการค้นหา การกรอง และการให้คะแนน)
- **ที่อยู่เก็บแบบมีโครงสร้าง** (`LeaderAddress`) ไม่ใช่ข้อความก้อนเดียว · **ประเทศเก็บเป็น `countryId`** ไม่ใช่ชื่อประเทศ
- **เปลี่ยนจังหวัด → ล้างเขต/อำเภอ และแขวง/ตำบลอัตโนมัติ** (กันข้อมูลไม่สอดคล้องกัน)
- **"วันที่พร้อมเริ่มงาน" ≠ "วันที่เริ่มร่วมงาน"** — อันแรกคือความพร้อมรับงานถัดไป อันหลังคือวันที่เข้ามาอยู่ในระบบ
- ฟิลด์ที่ขึ้นกับเงื่อนไข: ศาสนา = "ศาสนาอื่น" → ต้องระบุเพิ่ม · แหล่งที่มา = "ช่องทางอื่น" → ต้องระบุเพิ่ม · รูปแบบการรับงาน = "ตามช่วงเวลาที่กำหนด" → ต้องระบุวันที่เริ่ม–สิ้นสุด (สิ้นสุด ≥ เริ่ม)
- **ข้อมูลไม่บังคับที่ไม่ได้กรอก แสดงเป็น `—`** ในหน้ารายละเอียด และต้องไม่เกิด Runtime Error
- ผู้ใช้ทั่วไป **แก้ `createdAt` / `createdBy` ไม่ได้** (แสดงอ่านอย่างเดียว) · หมายเหตุภายในเห็นได้ตามสิทธิ์
- ทุกฟิลด์ใหม่ถูกบันทึกลง **ประวัติการแก้ไข (Audit)** แบบค่าเดิม → ค่าใหม่ โดยข้อมูลอ่อนไหวยังถูกปิดบัง

**ตัวกรองใหม่ในหน้ารายการ:** จังหวัด · พร้อมเริ่มงานภายในวันที่ (คอลัมน์ "พร้อมเริ่มงาน" แสดง "พร้อมทันที" สีเขียว หรือวันที่สีเหลืองเมื่อยังไม่ถึงกำหนด)

### ประวัติการทำงาน ≠ ประวัติงานทัวร์

| | ประวัติการทำงาน (`EmploymentHistory`) | ประวัติงานทัวร์ (`WorkHistory`) |
| --- | --- | --- |
| หมายถึง | บริษัท ร้านค้า องค์กร **สถานประกอบการ**ที่เคยทำงาน | **งานทัวร์ที่ได้รับมอบหมายในระบบ** |
| เก็บอะไร | ชื่อสถานประกอบการ · เบอร์โทร · เงินเดือน · ตำแหน่ง · ช่วงเวลา · เหตุผลที่ออก | เชื่อมด้วย `tourJobId` — **ไม่คัดลอกข้อมูลงานมาเก็บซ้ำ** |

**สถานะพร้อมรับงาน (5 สถานะ):** พร้อมรับงาน · ติดงาน · ลาพัก · ไม่พร้อมรับงาน · ระงับใช้งาน

ค่าเริ่มต้นเมื่อเพิ่มคนใหม่: **ประเภท = ทั่วไป · สถานะรับงาน = พร้อมรับงาน · สถานะข้อมูล = ใช้งาน**
เปลี่ยนประเภทเมื่อไหร่ ระบบ**เก็บ `TypeHistory` พร้อมเหตุผล**ให้อัตโนมัติ

**รหัสหัวหน้าทัวร์** — ระบบสร้างให้อัตโนมัติ (`TL-013`, `TL-014`, …) แก้ไขได้ และตรวจว่าไม่ซ้ำ

**รูปประจำตัว** — เลือกไฟล์รูปแล้วเห็น Preview ทันที เปลี่ยนหรือนำออกได้ ตรวจว่าต้องเป็นไฟล์รูป (JPG/PNG/WebP/GIF) และไม่เกิน **2 MB** ถ้าไม่มีรูปจะ fallback เป็น Avatar อักษรย่อชื่อ
เก็บเป็น **Data URL (Base64) ใน memory เท่านั้น** — ไม่อัปโหลดขึ้น Server

**ประเทศประจำ ≠ ประเทศที่เชี่ยวชาญ**
“ประเทศประจำ” = ประเทศที่บริษัทเรียกใช้ทำงานเป็นหลัก (มีประเทศหลักได้ 1 · เพิ่มเติมได้หลายประเทศ · เว้นว่างได้)
“ประเทศที่เชี่ยวชาญ” = ความสามารถที่ใช้จับคู่งาน (ดูหัวข้อถัดไป)

**เอกสาร (หลายรายการ)** — บัตรประชาชน / หนังสือเดินทาง / ใบอนุญาต / วีซ่า / ใบรับรอง / อื่น ๆ
แต่ละใบเก็บ: เลขที่ (⚠️ **ปิดบังก่อนบันทึกเสมอ** สำหรับบัตรประชาชนและพาสปอร์ต), ประเทศผู้ออก, วันที่ออก, วันหมดอายุ, ชื่อไฟล์จำลอง, **สถานะตรวจสอบ**, หมายเหตุ
ฟอร์มเตือน "ใกล้หมดอายุ / หมดอายุแล้ว" ทันทีขณะกรอก

**บัญชีธนาคาร (หลายบัญชี)** — ธนาคาร / ชื่อบัญชี / เลขบัญชี (⚠️ ปิดบังเสมอ) / สาขา / PromptPay / บัญชีหลัก / สถานะใช้งาน
เลือกบัญชีหลักใหม่ → ยกเลิกบัญชีหลักเดิมอัตโนมัติ

**ช่องทางติดต่อ** — เก็บเป็นรายการ (`ContactChannel[]`) เพิ่ม/ลบได้หลายรายการ รองรับ 10 ประเภท (โทรศัพท์ อีเมล LINE Facebook Instagram TikTok WhatsApp WeChat เว็บไซต์ อื่น ๆ) แต่ละรายการมีป้ายกำกับ ช่วงเวลาที่สะดวก และหมายเหตุ

- กำหนด **ช่องทางหลักได้เพียงรายการเดียว** (radio — เลือกใหม่จะปลดของเดิมอัตโนมัติ)
- ตรวจรูปแบบตามชนิด: เบอร์โทร / อีเมล / URL
- มีปุ่ม **คัดลอก** ทุกช่องทาง · ลิงก์โซเชียลเปิด **หน้าต่างใหม่** (`target="_blank"`)
- หน้ารายละเอียดแสดงเฉพาะช่องทางที่มีข้อมูล

**ภาษา** — ต่อภาษาเก็บ: ระดับโดยรวม (**บังคับ**), ฟัง/พูด/อ่าน/เขียน (ไม่บังคับ), ภาษาหลัก, ใบรับรอง + คะแนน + วันหมดอายุ, หมายเหตุ
ระดับมี 6 ขั้น: พื้นฐาน → พอสื่อสารได้ → ใช้งานได้ดี → คล่องแคล่ว → ใกล้เคียงเจ้าของภาษา → เจ้าของภาษา
**ห้ามเพิ่มภาษาซ้ำ** (ภาษาที่เพิ่มแล้วจะหายจากตัวเลือก) · **ภาษาหลักได้หนึ่งภาษา** · รายการภาษามาจาก Master Data

**ประเทศและเส้นทาง (ลำดับชั้น)** — นี่คือหัวใจของโมดูลนี้

```
ประเทศ (Country)
 ├─ ทุกเส้นทางในประเทศ   → coverage = 'all_routes'
 └─ เฉพาะเส้นทาง          → coverage = 'selected_routes' + routeIds[]
     ├─ ภูมิภาค (region)
     ├─ เมือง (city)
     ├─ สนามบิน (airport) — มีรหัส เช่น NRT, KIX
     └─ เส้นทางทัวร์ (tour_route)
```

กติกาที่บังคับใช้จริงในตรรกะค้นหา ([leaderProfile.ts](src/lib/logic/leaderProfile.ts) → `coversRoute`):

| กรณี | ผลลัพธ์ |
| --- | --- |
| เลือก **JAPAN — ทุกเส้นทาง** | ตรงกับ NRT, KIX, CTS, เส้นทางทัวร์ **ทุกรายการ** ในญี่ปุ่น |
| เลือก **เฉพาะ NRT** | ตรงกับ NRT เท่านั้น — **ไม่ถือว่าเชี่ยวชาญ KIX** |
| เลือก **NRT + KIX** | ตรงทั้งสอง แต่ไม่ตรง CTS |

แต่ละประเทศระบุเพิ่มได้: ระดับความเชี่ยวชาญ (เคยเดินทาง → เคยช่วยงาน → นำทัวร์ได้ → เชี่ยวชาญ → ผู้เชี่ยวชาญหลัก), จำนวนครั้งที่นำทัวร์, วันที่ทำล่าสุด, หมายเหตุ
**ห้ามเพิ่มประเทศซ้ำ** · ค้นหาด้วยประเทศ เมือง ชื่อเส้นทาง หรือรหัสสนามบินได้

**ประเภททัวร์และความถนัด** — แยก Master Data 2 หมวด

- **ประเภทกลุ่มลูกค้า** (8 รายการ): กรุ๊ปหน้าร้าน, กรุ๊ปเหมา, กรุ๊ปองค์กร, กรุ๊ปศึกษาดูงาน, กรุ๊ปครอบครัว, กรุ๊ปผู้สูงอายุ, กรุ๊ป VIP, กรุ๊ป Incentive
- **ทักษะและรูปแบบการทำงาน** (12 รายการ): ทำยอดขายเก่ง, ดูแล VIP, เอ็นเตอร์เทนเก่ง, ข้อมูลประวัติศาสตร์, ศิลปวัฒนธรรม, อาหารและท้องถิ่น, แก้ปัญหาเฉพาะหน้า, กรุ๊ปใหญ่, ดูแลเด็ก, ดูแลผู้สูงอายุ, ประสานงานต่างประเทศ, ถ่ายภาพ/Content

แต่ละรายการเก็บ: ระดับความถนัด (พอทำได้ / ทำได้ดี / ถนัด / เชี่ยวชาญ), จำนวนงาน, ปีประสบการณ์, คะแนน, หมายเหตุ
รายการพิเศษ **“ได้ทุกประเภท”** (`GROUP_ALL` / `SKILL_ALL`) จะ **ตรงกับทุกประเภทในการค้นหาและจับคู่งาน** และยังเลือกรายการที่โดดเด่นเป็นพิเศษเพิ่มได้อีก

**แท็บประวัติการทำงาน** — รวมประวัติ 2 แหล่งเข้าด้วยกันแต่ **แยกป้ายกำกับชัดเจน**

- 🔵 **จากระบบ** — งานที่สร้างในระบบ เชื่อมด้วยรหัสงาน กดเปิดหน้ารายละเอียดงานได้
- 🟡 **บันทึกย้อนหลัง** — เจ้าหน้าที่เพิ่มเอง เพิ่ม/แก้ไขได้ แนบชื่อไฟล์หลักฐาน (จำลอง)

มีสรุปด้านบน 8 ตัวเลข (จำนวนงาน, วันทำงานรวม, ประเทศที่เคยทำ, ลูกค้าที่ดูแล, คะแนนเฉลี่ย, งานล่าสุด, เส้นทางที่ทำบ่อยที่สุด, ประเภททัวร์ที่ทำบ่อยที่สุด)
กรองได้ตาม ปี / ประเทศ / เส้นทาง / ประเภทกรุ๊ป / คะแนน / แหล่งข้อมูล
ปุ่ม **“นำเข้าจาก Excel”** มีอยู่ แต่แจ้งว่ายังอยู่ในแผนพัฒนา

**หน้ารายละเอียด — ลดเหลือ 6 แท็บ** (ทุกแท็บอ่านจาก record เดียวกัน ไม่มีข้อมูล hardcode)

1. **ภาพรวม** — รูป · ข้อมูลพื้นฐาน · ประเภท · สถานะ · ช่องทางติดต่อ · ผู้ติดต่อฉุกเฉิน · ประเทศประจำ
2. **ความสามารถ** — ภาษา · ประเทศ/เส้นทางที่เชี่ยวชาญ · ประเภททัวร์ · ทักษะและความถนัด
3. **ประวัติการทำงาน** — จำนวนสถานประกอบการ · ประสบการณ์รวม · งานปัจจุบัน · ตำแหน่งล่าสุด · ตาราง · Timeline
4. **ประวัติงานทัวร์** — งานที่เชื่อมจากระบบ + ประวัติย้อนหลัง · ประเทศ/เส้นทาง · คะแนน · สถานะเคลียร์งาน
5. **เอกสารและการเงิน** — เอกสาร + แจ้งเตือนวันหมดอายุ · บัญชีธนาคารแบบปิดบัง
6. **ประวัติการแก้ไข** — ค่าเดิม → ค่าใหม่ · ประวัติเปลี่ยนประเภท · ผู้ดำเนินการ · วันเวลา

แท็บที่ไม่มีข้อมูลจะแสดง **Empty State พร้อมปุ่มเพิ่มข้อมูล** (ไม่แสดงข้อมูลของคนอื่นหรือข้อมูลตัวอย่างตายตัว)

**ประวัติการเปลี่ยนแปลง (Audit)** — บันทึก **หมวด · ค่าเดิม → ค่าใหม่ · เหตุผล · ผู้ดำเนินการ · วันเวลา** ทุกครั้งที่แก้ไข
ประเภทหัวหน้าทัวร์ · สถานะรับงาน · ประเทศประจำ · เส้นทางที่เชี่ยวชาญ · ภาษา · ความถนัด · ช่องทางติดต่อ · เอกสาร · บัญชีธนาคาร · การปิด/เปิดใช้งาน
⚠️ เลขเอกสารและเลขบัญชีในประวัติถูก**ปิดบัง** (`••••1234`)

กดปุ่ม **“ดูที่มาของคะแนน”** เพื่อเห็นคะแนนรายเกณฑ์ (เช่น `เส้นทาง 16/35`) พร้อมคำอธิบาย

### สูตรคำนวณการเคลียร์งาน

```
ยอดสุทธิ = ค่าใช้จ่ายที่บัญชีอนุมัติ − เงินทดรองที่ได้รับ

ยอดเป็นบวก  → บริษัทต้องจ่ายเพิ่มให้หัวหน้าทัวร์
ยอดเป็นลบ   → หัวหน้าทัวร์ต้องคืนเงินบริษัท
ยอดเป็นศูนย์ → เคลียร์พอดี
```

### ความสัมพันธ์ข้อมูล (เชื่อมด้วย ID ทั้งหมด — ไม่เชื่อมด้วยชื่อข้อความ)

```
TourLeader (createdAt/By, updatedAt/By)
 ├─ ContactChannel[]        (id คงที่ · isPrimary ได้ 1)
 ├─ LanguageSkill[]         → LanguageMaster (ชื่อภาษา)
 ├─ AssignedCountry[]       → CountryMaster (countryId)
 ├─ TourLeaderRouteSkill[]  → CountryMaster + RouteMaster (countryId / routeIds)
 ├─ TourTypeSkill[]         → customerGroups / workSkills (masterId)
 ├─ LeaderDocument[]        → CountryMaster (issuingCountryId)
 ├─ LeaderBankAccount[]     (isPrimary ได้ 1)
 ├─ Evaluation[]            → TourJob (jobId)
 ├─ TypeHistory[]           (ประวัติเปลี่ยนประเภท)
 └─ AuditEntry[]            (หมวด · ค่าเดิม → ค่าใหม่ · เหตุผล)

WorkHistory  = งานในระบบ (อ้าง TourJob ด้วย id — ไม่คัดลอกข้อมูลมาเก็บซ้ำ)
             + ประวัติย้อนหลังที่บันทึกเอง (WorkHistoryEntry, มี tourJobId ได้ถ้าเชื่อมกับงานในระบบ)
```

Child record ทุกตัวมี **ID ที่คงที่** (`newChildId()` — ไม่ใช้ array index) และการแก้ไขหัวหน้าทัวร์**ไม่ทำให้ประวัติงานที่เชื่อมอยู่หาย** เพราะประวัติงานอ่านจาก `jobs` โดยตรง

### หลักการที่ยึดไว้

- **แยก types / mock data / business logic / UI ออกจากกัน** — ไม่มีการคำนวณธุรกิจฝังใน Component
- **เปลี่ยนข้อมูลจำลองได้โดยไม่ต้องแก้ Component** — แก้เฉพาะไฟล์ใน `src/data/`
- **ทุกสถานะมีทั้งสีและข้อความกำกับ** ไม่สื่อความหมายด้วยสีเพียงอย่างเดียว
- **ไม่เก็บข้อมูลส่วนบุคคลจริง** — เลขบัตรประชาชนและเลขบัญชีธนาคารถูกปิดบังเสมอ (`x-xxxx-xxxxx-45-x`, `xxx-x-x1234-x`)

## 7. ข้อเสนอสำหรับการพัฒนารุ่นจริง

**ลำดับความสำคัญสูง**

1. **Backend + ฐานข้อมูล** — PostgreSQL + Prisma; ย้าย `src/lib/logic/*` ไปเป็น service layer ฝั่งเซิร์ฟเวอร์ได้ทันทีเพราะเป็นฟังก์ชันบริสุทธิ์อยู่แล้ว
2. **Authentication + Authorization จริง** — เช่น NextAuth หรือ SSO ขององค์กร แล้วบังคับสิทธิ์ที่ API ด้วย ไม่ใช่แค่ซ่อนปุ่มใน UI
3. **Audit log จริง** — ปัจจุบัน Timeline เก็บใน memory ควรเก็บเป็นตารางแยกที่แก้ไขย้อนหลังไม่ได้
4. **การอัปโหลดหลักฐาน** — S3/Blob storage + ตรวจชนิดและขนาดไฟล์

**ลำดับความสำคัญกลาง**

5. **แจ้งเตือนอัตโนมัติ** — LINE Notify / อีเมล เมื่อใกล้ครบกำหนดเคลียร์งาน เอกสารใกล้หมดอายุ หรือมีใบเบิกรออนุมัติ
6. **อัตราแลกเปลี่ยนอัตโนมัติ** — ดึงจาก API ธนาคารแห่งประเทศไทย แทนการกรอกมือ (ตอนนี้ดึงค่าเริ่มต้นจากข้อมูลตั้งต้น)
7. **ส่งออก Excel/PDF จริง** — ExcelJS / Puppeteer
8. **นโยบายค่าใช้จ่าย (Policy engine)** — เพดานทิป เพดานค่าเบ็ดเตล็ด ให้ตั้งค่าได้ในหน้าตั้งค่า แทนการ hardcode เหตุผลตอนตรวจ

**ประเด็นที่ควรถามผู้ใช้เพิ่มในรอบถัดไป**

- การเคลียร์งานต้องมีผู้อนุมัติกี่ระดับ? (ตอนนี้จำลองไว้ระดับเดียว)
- ค่าตอบแทนหัวหน้าทัวร์คิดแบบเหมาจ่ายต่องาน หรือรายวัน / มีเรตตามประเทศหรือไม่?
- เมื่อหัวหน้าทัวร์ตอบปฏิเสธงานที่เสนอไป ระบบควรทำอะไรต่อ? (ตอนนี้ย้อนกลับเป็น "รอจัดหัวหน้าทัวร์")
- กำหนดวันเคลียร์งาน 14 วันหลังกลับ เป็นค่ามาตรฐานที่ใช้จริงหรือไม่?
- ต้องรองรับผู้ช่วยหัวหน้าทัวร์มากกว่า 1 คนต่องานหรือไม่?
